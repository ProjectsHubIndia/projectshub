The Asset model in `core/models.py` (lines 792-809) defines eight fields covering the complete lifecycle of media asset tracking. The `name` CharField stores identifiers, `file` FileField handles uploads to `assets/`, `file_url` URLField allows external CDN references, `mime_type` CharField captures content types, `size_bytes` PositiveIntegerField tracks file size, `uploaded_at` DateTimeField auto-stamps creation, `notes` TextField documents usage context, and `is_used` BooleanField flags active status. ## AssetAdmin features

AssetAdmin (lines 1812-1869) registers the Asset model and configures list_display with six columns: preview (image thumbnail), name, mime_type, size_display (human-readable), is_used, uploaded_at. The preview method checks if mime_type starts with 'image/' and renders an `<img>` tag from either `obj.file.url` or `obj.file_url`, falling back to '—' for non-images. The size_display method converts size_bytes to B/KB/MB format with appropriate precision.

list_filter includes UnusedAssetFilter and 'mime_type', enabling the `?filter=unused` query parameter. search_fields covers name, notes, mime_type. ordering=('-uploaded_at',) sorts newest first. list_per_page=50 paginates large asset lists.

The get_queryset override checks `request.GET.get('sort')` and returns `qs.order_by('-size_bytes')` when sort='size_desc', implementing the `?sort=size_desc` requirement. No other sort values are handled, so the default ordering applies otherwise.

This creates ambiguity. If the goal was to replace the custom view with the Asset model admin, the URL mapping should redirect `/admin/assets/` → `/admin/core/asset/` (or use a custom admin URL override). **Likely**: The custom view was already handling some asset browsing logic, and the coder preserved it to avoid breakage. But the prompt's requirements (Asset model, UnusedAssetFilter, `?filter=unused`, `?sort=size_desc`) only apply to the ModelAdmin interface at `/admin/core/asset/`.
